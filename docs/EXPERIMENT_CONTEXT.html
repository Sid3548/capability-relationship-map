Two-Model Capability Removal Experiment

Persistent context handoff · created 2026-08-29 Asia/Calcutta · update this file whenever the protocol, code, or run state changes.

Research objective

Map how 15 capabilities are distributed across MLP intermediate channels by cumulatively ablating the least-active channels for a target capability in increments no larger than 0.1%, measuring how far the target capability remains intact and how all other capabilities change. Compare exactly two models under the same protocol.

Audit finding: prior Llama report is not a complete valid study

Do not cite the old Llama HTML as a completed experiment. Preserve it as provenance only.
  • The D/interlink job stopped after only coding and math. The log ends after those two targets, the remaining 13 matrix rows are initialized zeros, and no completion manifest exists. The report generator nevertheless emitted completion language.
  • The report labels values such as 3.34 as “Δaccuracy”; those values are actually read from the ΔNLL matrix. Absolute accuracy deltas cannot exceed 1 in magnitude.
  • The comprehensive runner performs one global stress sweep, not 15 target-conditioned removal envelopes. It therefore does not answer the main target-by-target question.
  • The runner uses only mean ablation for the comprehensive run, omits the required high control in the global sweep, uses only five random seeds at sparse points, ignores the accuracy-retention failure rule, and does not run the zero-ablation bound.
  • The supposed held-out calibration mean is computed from the same 600 evaluation items, causing leakage.
  • The high interlink mask is simply the top 5% for the target, not the documented target-specific-high set, and the report describes it inconsistently as top 20%.
  • The random control is globally permuted rather than matched to the target mask's per-layer removal counts.

Audit finding: the existing 600-prompt battery is heavily redundant

The old activation aggregates and A/B overlap maps must be recomputed after rebuilding the batteries.

There are 600 rows but only 365 unique exact prompts. Several capabilities are dominated by one repeated item: coding repeats one addition prompt 20 times; creative writing repeats one rainy-afternoon prompt 30 times; ethics repeats one scenario 25 times and all 40 correct labels are B; history repeats “Egypt is in Africa” 20 times; science repeats oxygen's symbol 20 times. MCQ labels are severely imbalanced. Because capture is performed on teacher-forced answer positions, these repetitions and answer-letter distributions can dominate the neuron ranking.

Audit finding: NLL/capture implementation needs correction

  • Prompt and gold are tokenized separately and their token IDs concatenated. For BPE tokenizers this can differ from tokenizing the actual concatenated text at the boundary.
  • Activation capture currently uses gold-answer positions only. That can measure answer-format/label-token circuitry more than the capability. The experiment must explicitly choose prompt-only, answer-only, or both and report sensitivity.
  • A single-reference NLL is not a valid standalone quality metric for creative writing and is weak for open-ended translation/summarization.
  • Relative NLL doubling is badly confounded when baseline NLL is already high; math and problem-solving showed 100% generation accuracy but baseline NLL around 11–13.

Run arithmetic

For 15 capabilities and 0.1% increments from 0.1% through 50%, there are exactly 7,500 ablated target-mask points (15 × 500), plus reusable unablated baselines. Evaluating all 15 capabilities × 40 prompts at every mask gives 4,500,000 prompt evaluations on the primary low-activation track per model. This is feasible only with batched teacher-forced/logit scoring; full generation at every point is not cheap.

Cost-controlled protocol proposal (awaiting researcher confirmation)

  1. Rebuild all batteries with unique, stratified items and balanced MCQ answer positions. Use separate localization and held-out evaluation items, or cross-fitting if the total must remain exactly 40 per capability.
  2. Static ranking, computed once per capability. Neuron = post-gating MLP intermediate channel feeding the down projection. Rank within each layer and remove the same fractional count per layer at every step.
  3. Primary curve: cumulative low-activation-first mean ablation, every 0.1% to 50%, teacher-forced NLL/logit-margin and task-specific score. Evaluate the target at every point; evaluate all 15 capabilities at a cheaper checkpoint schedule unless the researcher explicitly requires all 600 prompts at all 7,500 points.
  4. Controls: high-activation and layer-matched random at smoke gates and 1% checkpoints; five random seeds initially, expand only if confidence intervals are unstable. Zero ablation at checkpoints and around cliffs, not at all 500 points.
  5. Generation: baseline; every 5%; and dense 0.1–0.5% checkpoints around a detected bend. Greedy decoding and fixed parsers. Store per-item predictions, not only aggregate accuracy.
  6. Run a tiny architecture/hook smoke test on each model before any long run: verify exact tensor shape, one-channel intervention changes logits, ablated counts are exact, restoration is exact, and high removal hurts more than low removal.
  7. Run models sequentially on the one GPU. Every stage is resumable and atomic; incomplete matrices are represented by null plus completion masks, never zeros.

Open decisions requiring researcher confirmation

  1. Does “40 prompts per capability” mean 40 total, forcing a train/eval split or cross-fitting, or may we use 40 localization + 40 held-out evaluation prompts per capability?
  2. At each of the 7,500 target-mask points, must all 600 prompts be scored, or can all 600 be scored at checkpoints while the target capability is scored at every 0.1% point?
  3. Confirm that coding and math are included inside the 15 capabilities (7,500 points total), not two additional capabilities (8,500 points).
  4. For model comparability, should the experiment use the downloaded base checkpoints exactly, or instruction-tuned checkpoints for both families? Mixing base and instruct is not acceptable for the headline comparison.
  5. Approve redesigning the existing prompts/evaluators rather than attempting to preserve backward compatibility with the invalid old battery.
